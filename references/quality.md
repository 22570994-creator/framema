# 验收说明

自动检查与审看分开记录：

- build：分镜可解析、整数帧连续、时长一致、资源在工程内、音轨足够长、需要同步时存在锚点证据。
- check：上游实际浏览器运行、布局、对比度与动画检查；0 samples 不能算有效浏览器验证。
- verify：FFprobe 实际解码帧数、画幅、帧率、视频时长、音轨存在性、音频时长容差及 FFmpeg 全片解码。AAC 首尾填充采用编码级容差，不将其误当卡点误差。
- 人工/模型审看：首尾、镜头中点、转场两侧、字体、文字完整性、主体变化。写明实际看过的时间点。contact-sheet.png 是快速索引，必须结合单帧。
- 听感：没有实际审听就保持 audioListening=pending。没有可靠节拍锚点就不宣称卡点精确。

reports/qc-report.json 默认把美术和听感设为 pending，调用者审看后另写 review.json 记录证据，不能把脚本退出码当作用户美术批准。

交付说明写具体分辨率、时长和验证状态，避免“电影级”“完美同步”等无证据评价。只有 HTML 或工程时标明部分完成。

同题对照需要相同模型设置、简报、资产和近似预算，在独立运行中比较直接提示与 Skill。单一会话已经加载 Skill 后，不能将自制对照包装为盲测；没有真实 A/B 就报告未做。
